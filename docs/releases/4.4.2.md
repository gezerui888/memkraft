## MemKraft 4.4.2

Hermes turn timing no longer blocks the turn. No migration required.

- The Hermes provider used to write a delay-ledger record on every phase
  change. Hermes reports one before and one after each model call, and each
  write re-reads and folds the whole ledger under a lock with two fsyncs.
  On a 64 MB ledger (138k records) that cost about 2 s per write and 9 s per
  tool step.
- Phase time is now accumulated in memory. When a turn finishes, its task and
  one record per phase (active, wait, rework) are written once by a
  background thread. `shutdown()` closes open turns and drains the queue
  (`MEMKRAFT_TIMING_DRAIN_S`, default 10 s). `flush_timing(timeout)` waits for
  pending writes.
- Phase records are per-phase totals rather than one record per transition;
  ETA estimates use task records and are unaffected.

### Verification

- `tests/test_timing_hot_path.py`: phase transitions make no ledger writes; a
  finished turn writes one task and one record per phase; shutdown drains.
- Copy of a live 64 MB ledger, one turn with 20 tool steps: time spent in
  timing on the turn path dropped from 187.2 s to under 0.1 s; the background
  write took 13.2 s.
