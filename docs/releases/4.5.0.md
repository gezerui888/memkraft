## MemKraft 4.5.0

Owner sayings now record what actually enforces them. No migration required.

An agent can store a standing rule verbatim and still break it next week if
nothing but the text holds it. 4.5.0 makes that gap visible: every live
saying gets an enforcement level, and a report lists the ones nobody has
classified yet and the ones whose enforcing file disappeared.

- `saying_classify(saying_id, level, by=paths, note=)`. Levels:
  `code`, `config`, `check` (need at least one enforcing path),
  `prose` (standing rule that exists only as text), `oneoff`
  (single task or fact). Latest row wins; repeating the same
  classification is a no-op.
- Rows are appended to `<owner_dir>/enforcement.jsonl`. `sayings.jsonl`
  is untouched and stays verbatim-only.
- `saying_enforcement_report(root=)` returns `total`, `levels`,
  `unclassified`, `broken` (enforcing paths missing under `root`),
  `prose` and `ok`. It returns ids only, never saying text, so it is safe
  to log or feed into a cron monitor.
- `saying_search` hits carry `enforcement` (`unclassified` when none).
- CLI: `memkraft owner classify ID LEVEL --by PATH`, `memkraft owner
  enforcement [--root DIR] [--json]` (exit 1 when not ok).
- Hermes provider tool: `owner_saying_classify`.

### Verification

- `tests/test_owner_enforcement.py`: new sayings start unclassified;
  enforced levels require a path; unknown ids and levels are rejected; a
  deleted enforcer shows up as broken; the latest classification wins and is
  idempotent; retired sayings leave the report; saying text never appears in
  the report; `sayings.jsonl` holds only saying rows; CLI exit codes.
- Live owner ledger (80 sayings) migrated from an external JSON map: 80/80
  classified, 0 broken, `sayings.jsonl` byte-identical before and after.
