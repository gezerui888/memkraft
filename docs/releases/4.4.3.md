## MemKraft 4.4.3

Hermes recall no longer spends its five slots on copies or cron notices.
No migration required.

- Every completed Hermes turn is stored twice (an artifact and a live-note
  chunk), and every cron run re-stores the same scheduler preamble. Recall
  therefore often returned the same turn twice, or five cron preambles, in
  its top five.
- `_recall_hits` now collapses hits whose text is the same turn (speaker
  prefix, JSON wrapping and Markdown punctuation ignored) and drops cron
  scheduler preambles. The first, most relevant copy wins and the search
  window still widens (12 → 80 → 240) until five distinct hits are found.
  Cron preambles are returned only when nothing else matches.
- Stored files are unchanged; this is a read-path filter.

### Verification

- `tests/test_recall_diversity.py`: same-turn copies collapse, cron
  preambles are dropped (and kept only as a last resort), distinct hits keep
  their order, a polluted store still yields five distinct hits.
- 20 real recent queries (15 human requests, 5 cron prompts) against a live
  Hermes store: duplicate slots 26/100 → 0, cron-preamble slots 21/100 → 0,
  queries with two or more polluted slots 7 → 0. Total returned hits 100 → 91
  (three cron-prompt queries had fewer than five distinct matches). Median
  recall time unchanged at 0.07 s.
